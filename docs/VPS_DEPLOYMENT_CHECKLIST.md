## 🎯 Pre-VPS Preparation (Do This NOW)

### 1. Generate & Secure Secrets

```bash
# Encryption key for secret vault (REQUIRED - do not lose!)
openssl rand -hex 32 > .env.local.VALET_KEK_HEX

# Cron job secret (same for all cron endpoints)
openssl rand -hex 32 > .env.local.CRON_SECRET

# Webhook secret (optional HMAC verification)
openssl rand -hex 32 > .env.local.WEBHOOK_SECRET
```

**Store securely:** Save these files in your deployment environment's secrets manager, NOT in git.

### 2. Circle Console Setup

Register entity secret and create API keys:

```bash
# Run once on VPS to register entity secret
node --import tsx scripts/register-entity.ts
```

**Required credentials from Circle Console:**
- `CIRCLE_API_KEY` (Developer Services → Keys)
- `CIRCLE_ENTITY_SECRET` (generated by `register-entity.ts`)
- `CIRCLE_APP_ID` (User-Controlled Wallets app)
- `PLATFORM_CIRCLE_WALLET_ID` (DCW wallet ID)
- `CIRCLE_USDC_TOKEN_ID` (Arc USDC token ID)

**Configure webhook endpoint in Console:**
- Go to Developer Services → Webhooks
- Add webhook URL: `https://<your-domain>/api/webhooks/circle`
- Select events: `wallet.*`, `transaction.*`, `user.*`
- Copy the webhook IP addresses (for IP allowlist): [Check here](https://developers.circle.com/docs/webhook-ips)
- Test endpoint first

### 3. Upstash Redis Setup (Rate Limiting)

Create free Redis instance at https://upstash.com:

1. Create account + workspace
2. Create new Redis database (free tier OK)
3. Get connection details:
   - `UPSTASH_REDIS_REST_URL` (REST URL)
   - `UPSTASH_REDIS_REST_TOKEN` (Authorization token)
4. Configure firewall if needed (allow your VPS IP)

**Why?** Without Redis, rate limiting falls back to in-memory (not secure for production).

### 4. Cloudflare Turnstile Setup (Bot Protection)

Register at https://cloudflare.com/turnstile:

1. Create site key for domain `<your-domain>`
2. Get:
   - `NEXT_PUBLIC_TURNSTILE_SITE_KEY` (public key)
   - `TURNSTILE_SECRET_KEY` (secret key)
3. Or disable it during initial deployment (comment out verification in `email-otp/route.ts`)

**Option B: Skip Turnstile temporarily** — comment out verification in dev phase:
```typescript
// In app/api/auth/email-otp/route.ts line 25-27
if (process.env.NODE_ENV !== "production") return null;
```

### 5. SMTP Configuration (Email Delivery)

**Option A: Use Brevo (formerly Sendinblue)** - Free tier available
1. Sign up at https://brevo.com
2. Verify sender domain
3. Get SMTP credentials:
   - `SMTP_HOST` = smtp-relay.brevo.com
   - `SMTP_PORT` = 587
   - `SMTP_USER` = Your SMTP username
   - `SMTP_PASS` = Your SMTP password
   - `RECOVERY_EMAIL` = noreply@yourdomain.com

**Option B: Use SendGrid / Mailgun / SES** — pick any provider with free tier

**IMPORTANT:** Also configure email delivery in **Circle Console**:
- Go to Wallets → User Controlled → Configurator → Email
- Enter your SMTP credentials (stored encrypted by Circle)
- Set email template: Must contain `{{ email.otp }}` placeholder
- Send test email to verify

### 6. Supabase Cloud Setup

1. Create project at https://supabase.com
2. Get credentials from Settings → Database:
   - `NEXT_PUBLIC_SUPABASE_URL` (Project URL)
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` (Public anon key)
   - `SUPABASE_SECRET_KEY` (Service role key — KEEP SECRET!)
3. Restore migrations from `supabase/migrations/`:
   ```bash
   # On VPS
   npx supabase db push
   ```

### 7. Database Migration & Seeding

**Critical:** Run migrations AFTER fresh DB setup:

```bash
cd /path/to/slimemarket-app

# Stop containers first (if Docker)
docker stop $(docker ps -a --filter "name=supabase" --format "{{.Names}}")
docker rm $(docker ps -a --filter "name=supabase" --format "{{.Names}}")

# Remove old volumes
docker volume prune -f

# Start fresh
npx supabase start

# Reset database
npx supabase db reset

# Apply all migrations
npx supabase migration up
```

**Verify no duplicate versions:** Ensure all migration files have unique version numbers (checked previously: 0019, 0021, 0022, 0043, 0044 were fixed).

### 8. Deploy Smart Contract

Deploy MarketEscrow.sol with v4 fee model:

```bash
# Fund deployer wallet first
node scripts/generate-deployer.mjs --fund 5

# Deploy contract (auto-writes ESCROW_CONTRACT_ADDRESS to .env.local)
npx tsx --env-file=.env.local contracts/deploy.ts
```

**Post-deployment steps:**
1. Note contract address written to `.env.local` (e.g., `0xda76142cd1d3...`)
2. Reset indexer state:
   ```sql
   DELETE FROM indexer_state;
   ```
3. Null stale IDs:
   ```sql
   UPDATE orders SET on_chain_order_id = null, on_chain_tx_hash = null WHERE on_chain_order_id != '0';
   UPDATE wl_deals SET on_chain_deal_id = null, on_chain_tx_hash = null WHERE on_chain_deal_id != '0';
   ```
4. Verify contract ready:
   ```bash
   curl http://localhost:3000/api/health
   # Should return: {status:"ok", checks:{contractReady:true}}
   ```

### 9. Build Frontend Bundle

Generate static assets:

```bash
npm run build
npm run generate-bundles  # If using webpack bundle generation
```

Place generated `.jsx` files in `public/` directory.

## 📋 Post-Deployment Verification

After deploying to VPS:

### 1. Health Check
```bash
curl https://<your-domain>/api/health
```

Expected response:
```json
{
  "status": "ok",
  "checks": {
    "db": true,
    "circle": true,
    "escrow": true
  }
}
```

If `contractReady=false` → check:
- `ESCROW_CONTRACT_ADDRESS` env var is correct
- Contracts deployed successfully
- RPC URL accessible

### 2. Rate Limiting Test
Send multiple OTP requests rapidly:
```bash
curl -X POST https://<your-domain>/api/auth/email-otp \
  -H "Content-Type: application/json" \
  -d '{"action":"request","email":"test@example.com","turnstileToken":"fake"}'
```

Should succeed first time → fail with 429 after 3 attempts/hour.

### 3. Frontend Test
Visit homepage and test:
- Browse products ✓
- Checkout flow → shows "Fee (2%)" ✓
- OTP login → email arrives ✓
- PIN setup → hosted UI works ✓

### 4. Monitor Logs
Watch for errors:
```bash
# If using PM2
pm2 logs slimemarket

# If using Docker
docker logs slimemarket_app
```

Look for:
- `[rate-limit] Running without Redis` → Configure Upstash!
- `Circle webhook: signature verification failed` → Check webhook URL/IP
- `Failed to process notification` → Check Circle event payloads

## 🛠 Troubleshooting Common Issues

### Issue: Webhook returning 403 Unauthorized
**Cause:** IP not in allowlist
**Fix:** Get Circle's outbound IPs and update `CIRCLE_WEBHOOK_IPS`

### Issue: OTP emails not arriving
**Causes:** 
1. SMTP not configured
2. Circle Console email config not updated  
**Fix:** Configure both .env AND Circle Console

### Issue: `/api/health` returns `contractReady: false`
**Causes:**
1. `ESCROW_CONTRACT_ADDRESS` wrong
2. RPC unreachable
3. Contract not deployed
**Fix:** Verify env var matches deployed contract address

### Issue: Rate limiting blocks legitimate requests
**Causes:**
1. Upstash down
2. Wrong Redis URL
**Fix:** Check Upstash status, verify connection string

### Issue: Turnstile challenge not loading
**Causes:**
1. Site key mismatch
2. Domain not allowed in Cloudflare
**Fix:** Register domain in Turnstile dashboard
